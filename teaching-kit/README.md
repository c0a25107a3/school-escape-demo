# 学校脱出ゲーム：5人で進める実装教材

第13グループの自主教材です。教員の講義資料とは別に、共通ベースから各機能を作る手順をまとめています。
説明スライドは22枚、演習は共通1冊と担当別5冊です。担当と仕様は話し合いで確定してください。

3. 下の担当演習を読み、練習1から順番に実装する。
4. 動作確認表を埋め、代表者と接続してからPRを出す。

## 実装の前に

- [共通型・練習用コード](starter/README.md)で接続の約束を確認します。
- 既存機能を移して同じ動作を確認し、その後に新機能を追加します。
- 各演習は実装の設計図です。TODOや抜粋は、そのままで完成ゲームにはなりません。
- 基準ソースは [kusupon/ProjExD_Group13 の game.py](https://github.com/kusupon/ProjExD_Group13/blob/33fe9905c183b321d1988d66041feb8b7e74998f/game.py)、コミット `33fe9905c183b321d1988d66041feb8b7e74998f` です。
- 代表者のmainが更新された場合は、変更箇所と呼び出し方を比較してから進めます。
- 教材中の役割・操作・数値は整合する提案です。変える場合は共通演習も直します。

## 相談から完成まで

| 段階 | 進める内容 | 次へ進む条件 |
|---|---|---|
| 相談 | 名前・担当・必須機能・共通API・確認日時を決める | 全員が担当と境界を説明できる |
| 準備 | Fork、起動確認、共通型、Worldの枠 | 5人が同じ版を起動できる |
| 個別実装 | 演習を段階ごとに実装・commit | 各担当の動作確認表を満たす |
| 統合 | World→仕掛け→主人公→敵AI→ミッション | 1つ追加するたび基本操作が動く |
| 完成 | 両ステージの通しプレイ、調整、README、提出 | 他の人が説明だけで起動・脱出できる |

教員の第5回・第6回の指示と締切を優先してください。共通ベースと本人の追加実装をREADMEで分けます。
素材やコードの出典を残し、ライセンスは権利を確認してから設定します。
